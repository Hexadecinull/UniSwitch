# Code of Conduct

## The short version

Be respectful, assume good faith, and remember there's a person on the other end of every issue, pull request, and comment. Disagreement about code and design decisions is normal and welcome, disrespect toward people is not.

## Scope

This applies to all project spaces: the GitHub repository (issues, pull requests, discussions, comments), any project chat or forum that gets set up, and anywhere else someone is representing the project in an official capacity.

## Expected behavior

- Assume good faith. Most disagreements come from different context or experience, not bad intent.
- Give constructive feedback. "This approach has a problem, here's why, here's an alternative" is useful. Pure criticism without a path forward isn't.
- Accept that maintainers and other contributors can decline a suggestion or close an issue, and that this isn't personal.
- Respect people's time. Not every issue or pull request gets an instant response, this is a volunteer-driven project.
- Welcome newcomers. Everyone contributing today was new to the codebase once.

## Unacceptable behavior

- Harassment, insults, or personal attacks directed at anyone, whether about their code, their identity, or anything else.
- Discriminatory jokes, language, or imagery.
- Publishing anyone's private information without their explicit consent.
- Sustained disruption of discussions, issues, or pull requests.
- Any conduct that would reasonably be considered inappropriate in a professional setting.

## Reporting

If you experience or witness behavior that violates this code, report it by opening a private security advisory on the repository (see [`SECURITY.md`](./SECURITY.md) for how) or by contacting a maintainer directly if you know how to reach one. Reports are handled as confidentially as the situation allows.

## Enforcement

Maintainers are responsible for clarifying and enforcing this code, and may take any action they deem appropriate in response to behavior they consider inappropriate, threatening, offensive, or harmful, up to and including a temporary or permanent ban from project spaces. Maintainers who don't follow or enforce this code in good faith may face consequences from the project's leadership in turn.
